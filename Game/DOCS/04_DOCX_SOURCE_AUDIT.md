## 1. EXECUTIVE SUMMARY

Обход дерева `main` подтвердил **7 `.docx`** в архивном слое `IMPORT(INCOMPLETED, DONT DELETE)/`.

Все 7 файлов были идентифицированы по пути, размеру и Git blob SHA. Для бинарного доступа GitHub-коннектор также вернул Base64-представление DOCX как ZIP/XML-контейнера.

Однако требуемый локальный этап `ZIP -> XML -> текст` в текущей среде не удалось выполнить: контейнерный runtime не имеет рабочего сетевого доступа к GitHub (`Could not resolve host: github.com`), а доступный GitHub-коннектор не предоставляет полученный бинарный blob как локальный файл. Попытка передать DOCX через текстовый fetch закономерно отклоняется как binary content.

Поэтому этот документ **не делает вид, что текст DOCX был извлечён**. Никакие характеристики, числа, диалоги, таблицы или правила из нераспакованного DOCX не объявляются подтверждёнными.

Это частичный аудит состояния источников, а не завершённое восстановление DOCX-контента.

### Что подтверждено уже сейчас

- в архиве есть 7 DOCX;
- все 7 относятся к конкретным игровым ассетам;
- бинарное содержимое реально существует и доступно через Base64-представление;
- DOCX — ZIP/XML-контейнеры; в проверенном бинарном payload видны стандартные части `word/document.xml`, `word/styles.xml`, `word/settings.xml`, `word/fontTable.xml`, `word/_rels/document.xml.rels`, `word/theme/theme1.xml`, `word/numbering.xml` и `[Content_Types].xml`;
- нельзя использовать фактический текст DOCX как канон до декомпрессии и проверки XML.

### Что не подтверждено этим аудитом

Не подтверждены из содержимого DOCX:

- HP/урон/скорость/AI врагов;
- конкретные параметры оружия;
- эффекты предметов;
- NPC-функции, диалоги и квесты;
- конкретные механики зданий;
- таблицы и числа;
- любые дополнительные lore-факты;
- наличие/смысл изображений **внутри** самих DOCX;
- точная структура таблиц, списков и заголовков.

## 11. REPRODUCTION NOTE

Для завершения именно **source extraction** следующий агент/исполнитель должен получить бинарные DOCX как локальные файлы и выполнить минимум:

```text
DOCX -> ZIP -> word/document.xml -> XML parse -> text/list/table reconstruction
                         -> word/_rels/document.xml.rels
                         -> word/media/* (if present)
                         -> document relationships / numbering / styles
```

После этого каждое содержательное утверждение должно пройти отдельную классификацию:

- `CONFIRMED SOURCE`
- `CROSS-SOURCE CONFIRMED`
- `DOCX-ONLY`
- `CONFLICTING`
- `UNCERTAIN`

До выполнения этого шага характеристики из DOCX не являются подтверждённым каноном.
